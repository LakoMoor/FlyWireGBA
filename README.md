# FlyWireGBA

[![CI](https://github.com/LakoMoor/FlyWireGBA/actions/workflows/ci.yml/badge.svg)](https://github.com/LakoMoor/FlyWireGBA/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/LakoMoor/FlyWireGBA)](https://github.com/LakoMoor/FlyWireGBA/releases/latest)

Запускаемый ROM для **Game Boy Advance**, с процедурной 3D-мухой, автономным и ручным движением, нейронной картой и телеметрией. Скачайте **[готовый `.gba` из GitHub Releases](https://github.com/LakoMoor/FlyWireGBA/releases/latest)** и откройте его в mGBA или загрузите на GBA через совместимый flash-картридж. После локальной сборки ROM находится в `dist/fly.gba`.

## Что работает

- Интерфейс с отдельной сценой наблюдения, боковой панелью, постоянными вкладками и крупными значениями метрик.
- Программная перспективная 3D-отрисовка: объёмные голова, грудь, брюшко и глаза; крылья, усики, шесть ног, тень, еда и препятствия.
- Анимации покоя, ходьбы с чередованием опорных троек ног, поворота, взлёта, полёта, посадки, кормления с хоботком, чистки и отдыха.
- Автономный поиск сахара, обход/перелёт препятствий, голод и восстановление энергии. Ручное управление.
- Обычный 3D-вид, приближённый 3D-вид и быстрый 2D-вид; мини-карта арены.
- Реальная компактная подсеть **FlyWire FAFB v783: 128 нейронов, 2048 направленных связей**. Включает 20 сохранившихся в этом снимке сахарных сенсорных нейронов и один MN9 из списков авторов Shiu et al.; остальные узлы выбраны по анатомическим путям между ними.
- Карта активности: вспышки спайков, связи выбранного нейрона, счётчики входящих/исходящих связей, точный FlyWire root ID и его модельный потенциал. Показ связей остальных узлов отключён, чтобы карта оставалась читаемой.
- Метрики: измеренные FPS и загрузка CPU, время симуляции, скорость и путь, спайки в секунду по всей сети, число недавно активных нейронов, контакт, тики кормления и столкновений, график спайков за последние 4 секунды. Второй экран метрик показывает время/долю каждого поведения, энергию, голод, запах, высоту, стимул сахара и выход MN9.
- Пауза и сброс сеанса. Симуляция работает по аппаратному таймеру с шагом 1/30 секунды независимо от скорости графики.

## Управление

| Кнопка GBA | Действие |
|---|---|
| L / R | Арена → нейронная карта → метрики → справка |
| Select | Автономное / ручное управление |
| Вверх / вниз | Вперёд / назад в ручном режиме на арене |
| Влево / вправо | Поворот в ручном режиме на арене |
| B, удерживать | Полёт; отпускание запускает посадку |
| A, удерживать | Чистка |
| A+B, нажать вместе | Обычный 3D → приближённый 3D → 2D |
| Start | Пауза / продолжение |
| D-pad на карте нейронов | Выбор нейрона |
| A на карте нейронов | Показ / скрытие связей |
| B на экране метрик | Общая телеметрия / метрики тела и поведения |
| A на экране метрик | Сброс сеанса |

Для полного ручного управления сначала нажмите Select. На страницах нейронов и метрик муха продолжает автономную симуляцию, если включён AUTO. Кормление начинается при контакте с сахаром на земле, а поступление энергии зависит от спайков MN9. Движение и все модельные величины используют условные единицы.

## Что перенесено из FlyWire, а что является демонстрацией

**Анатомические связи и root IDs взяты из реальных данных.** Полный коннектом, анатомическая геометрия мозга, оригинальная биомеханическая модель тела и научно откалиброванные нейронные параметры в ROM не перенесены.

Это уменьшенная демонстрация: из выбранных 128 узлов сохранены 2048 наиболее сильных внутренних связей. Знаки связей взяты из опубликованной таблицы; веса агрегированы и квантованы. Спайки рассчитывает целочисленная LIF-сеть с шагом 33.3 мс, порогом 100 условных единиц, утечкой 1/8 и рефрактерностью в один тик. Это **не воспроизведение** модели Shiu с её временными параметрами и не биологически точный «полный мозг мухи».

Карта нейронов — схематическая раскладка, без настоящих координат сом. Тело — собственная процедурная сетка. Навигация, ходьба, полёт, чистка и энергетика заданы компактным контроллером; реальная подсеть управляет только разрешением кормления через MN9. Это явно обозначено и в самом ROM.

У GBA 256 КБ EWRAM и 32 КБ IWRAM, поэтому хранение и расчёт полного мозга с сотнями тысяч нейронов и миллионами связей здесь заменены небольшой подсетью. [Описание памяти GBA](https://mgba-emu.github.io/gbatek/#gba-memory-map).

## Сборка и проверки

```sh
make             # Clang с ARM backend, LLD, llvm-objcopy и Python 3
make test        # Тесты поведения, ASan/UBSan, происхождения данных и заголовка ROM
make preview     # Статические PPM-кадры тем же кодом на компьютере
```

`tools/build.py` находит LLVM в PATH и стандартном каталоге Homebrew; LLD может использоваться из установленного Rust. Пути можно задать переменными `CLANG`, `LD_LLD`, `LLVM_OBJCOPY`. devkitARM и сторонние библиотеки для сборки самого ROM не нужны. На Ubuntu установите `clang lld llvm`; для полного теста в mGBA зависимости перечислены в [CONTRIBUTING.md](CONTRIBUTING.md). Сгенерированные шрифт и палитра уже входят в исходники; при необходимости их можно обновить `python3 tools/assets.py`.

ROM и ELF/карта размещения создаются в `build/`, копия ROM — в `dist/`. `make clean` удаляет только промежуточный `build/`.

Для повторного извлечения подсети нужны NumPy, PyArrow, исходная таблица `Connectivity_783.parquet` и `figures.ipynb` из репозитория авторов:

```sh
python3 tools/import_connectome.py /path/Connectivity_783.parquet /path/figures.ipynb
make
```

Алгоритм: трёхшаговая прямая и обратная анатомическая релевантность от сахарных рецепторов к MN9; затем индуцированная подсеть и отбор 2048 связей по модулю веса. Преобразование веса: `sign(w) * round(sqrt(abs(w)) * 7)`, ограничение ±96. Исходные суммарные веса и IDs сохранены в [docs/connectome_edges.csv](docs/connectome_edges.csv), параметры и SHA-256 исходных данных — в [docs/connectome.json](docs/connectome.json). Второй MN9 и один из 21 исходного сахарного ID отсутствуют в скачанной таблице v783 и исключены, а не заменены искусственными узлами.

Проверка настоящего ROM выполнена в **ядре mGBA 0.10.5**, собранном отдельно. `tools/emulator_check.c` (запуск через `tools/run_emulator_check.py --source /path/mgba --build /path/mgba-build`) проверяет загрузку, движение, полёт/посадку, чистку, кормление, три вида, страницы метрик и паузу, читая память эмулируемой GBA; кадры в `docs/` получены из этого ROM. На физической GBA пока не проверено. Конкретная производительность и расход памяти записаны в [docs/validation.md](docs/validation.md).

## GitHub CI/CD и релизы

На каждом push в ветку и pull request CI собирает ROM, запускает тесты с ASan/UBSan, проверяет происхождение данных и заголовок картриджа, затем запускает ROM в mGBA. Проверенные ROM, ZIP, контрольные суммы и кадры сохраняются как артефакты workflow.

Push тега `vX.Y.Z` запускает релизный workflow. После успешных проверок он публикует `.gba`, ZIP с инструкцией и лицензиями, `SHA256SUMS` и manifest в GitHub Release. Версия тега должна совпадать с файлом `VERSION`; предварительные теги `-alpha.N`, `-beta.N`, `-rc.N` создают prerelease. Для публикации используется стандартный `GITHUB_TOKEN` репозитория.

```sh
make all test
python3 tools/package_release.py --tag v0.1.0  # локальная проверка упаковки
```

[Порядок выпуска следующей версии](CONTRIBUTING.md). Исходники и Actions закреплены SHA/хешами, персональные токены в проекте не нужны.
